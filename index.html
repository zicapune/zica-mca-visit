Code Lab 1 of 7 · Texture

    
Every photo is a 2D array.

    

      

        
  filter.js

        
You learned this as 2D arrays and matrices.

        
A sunset. Or is it?

      

      

    

    
    
Step 1 zooms into the pixels so the numbers appear. Step 2 turns it into edge detection (C=8, N=−1). Step 3 makes it a blur (all 1s). Then drag C and N yourself. Line: "Every filter in Photoshop and Instagram is a small grid of numbers sliding over a big grid of numbers. That is a nested for-loop you wrote in second semester." Upload media/lab/photo.jpg to use a real photo instead of the generated sunset.

  

  
  

    
Code Lab 2 of 7 · Modelling

    
Recursion grows trees.

    

      

        
  tree.js

        
You learned this as Recursion.

        
One line. Depth = 1.

      

      

    

    
    
Step 1 grows the tree from depth 1 to 11 live. Step 2 changes the angle to 88° (geometric fractal). Step 3 returns to a natural tree. Drag ANGLE slowly for the "wow". Line: "Remember recursion and the base case? Studios grow forests like this instead of modelling every branch."

  

  
  

    
Code Lab 3 of 7 · Environments

    
One function. Infinite worlds.

    

      

        
  terrain.js

        
You learned this as Functions and randomness.

        
A world made of one noise function.

      

      

    

    
    
Step 1 scrolls the seed to show endless new worlds. Step 2 starts the fly-over. Drag HEIGHT to flatten or raise mountains, SCALE to zoom the landscape. Line: "Open-world games generate terrain from functions like this, so the world never has to be stored in full."

  

  
  

    
Code Lab 4 of 7 · Rigging

    
Rigging is just maths.

    

      

        
  ik.js

        
You learned this as Trigonometry and loops.

        
A robot arm reaching for a target.

      

      

    

    
    
Move your mouse over the panel and the arm follows it; leave it and the target wanders on its own. Step 1 changes it to 14 short bones. Line: "This is inverse kinematics. Every character that reaches, walks or grabs uses an IK solver. Two loops, run every frame."

  

  
  

    
Code Lab 5 of 7 · Animation and UI/UX

    
One curve decides "smooth".

    

      

        
  card.css

        
You learned this as CSS.

        
Linear: correct, and lifeless.

      

      

    

    
    
Top lane is always linear for comparison. Step 1 = ease-out, step 2 = springy overshoot. Drag Y1 above 1 for bounce. Line: "Same code, same 0.9 seconds. Four numbers decide whether your app feels cheap or premium. That is UI/UX meeting front-end."

  

  
  

    
Code Lab 6 of 7 · Lighting and rendering

    
This code runs for every pixel.

    

      

        
  glow.frag

        
You learned this as Parallel computing.

        
A shader: a tiny program the GPU runs for every pixel at once.

      

      

    

    
    
Point at the counter in the corner: millions of runs a second, live. Step 1 raises FREQ, step 2 raises SPEED and GLOW. Line: "Every light, every water surface and every glow you see in a game is a program like this running on the graphics card."

  

  
  

    
Code Lab 7 of 7 · VFX and crowds

    
Three rules make a flock.

    

      

        
  flock.js

        
You learned this as Algorithms and simulation.

        
240 birds. Three rules. Nobody in charge.

      

      

    

    
    
Move the mouse into the flock and it scatters (the mouse acts as a hawk). Step 1 = chaos, step 2 = tight swarm. Line: "This is Craig Reynolds' boids algorithm from 1986. Flocks, crowds and swarms in films and games still start from these three rules."
